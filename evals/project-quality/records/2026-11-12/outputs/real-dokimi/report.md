## Evidence and risks

**R1 — Partial grades are intentionally valid grades, creating a consumer interpretation risk.** The CLI refuses a run with no graded evaluations (`dokimi/commands/answer_formats.py:42–68`). Empty/errored answers become errors; retrieval placeholders remain unscored (`dokimi/eval/reference_run.py:95–115`). `Grade.score` excludes unsupported, absent, and zero-weight checks; an actual judge failure suppresses the whole grade (`dokimi/eval/reference_checks.py:108–139`). However, a passing deterministic check beside an unrequested judge or timed-out regex can yield 100% and pass. Summary counters preserve that incompleteness (`reference_run.py:44–67`); tests deliberately assert it (`tests/test_reference_checks.py:148–172`). Empty-answer and judge-failure regressions have concrete assertions (`:423–492`). This is documented semantics, not evidence of a defect. End-to-end consumer protection against presenting that partial pass as a fully verified outcome was **not-found-in-inspected-scope**. Missing grading blocks are counted, but unanswered questions are outside the answer-driven traversal (`reference_run.py:119–136`), so its denominator must not be mistaken for suite completion.

**R2 — Static checking has useful boundaries but findings alone are not inspection coverage.** `script_findings` skips checkout-root bundles, depends on available tools, caps consideration at 200 files and one megabyte per file, and silently omits unreadable/oversized files (`dokimi/external/script_checks.py:65–118,129–161`). Representative tests assert syntax warnings and sanitized subprocess inputs (`tests/test_catalog_validate_scripts.py:79–124`); some shell cases explicitly skip without Bash (`:25–27,90–96`). Thus an empty findings list cannot establish that every script was parsed. Documentation acknowledges these limits (`docs/external-content.md:251–267`). Repository static claims are schema-checked and can supersede matching framework claims; they are supplied evidence, not independently verified truth (`dokimi/repos/l0/__init__.py:56–93`; `tests/test_repo_l0.py:204–225`).

**Existing strengths:** catalog evaluation explicitly records `checks_only`, `no_tasks`, and `not_measured`, and rejects an empty catalog (`dokimi/external/catalog_eval.py:97–114,124–155`). Tests assert static pass without runtime credit and verify payload scripts do not execute (`tests/test_catalog_eval.py:63–105,352–375`). CI config invokes offline pytest with outcome/journey receipts (`.github/workflows/ci.yml:318–334`) on PR/main/manual/scheduled events (`:6–16`). These are implemented assertions and configured execution, not observed runs or branch protection. Mutation CI is explicitly advisory (`.github/workflows/mutation.yml:4–10,44–49`).

## Proposed implementation handoff

1. **R1: completeness contract pilot.** Extend `tests/test_reference_checks.py` and add `tests/test_reference_completeness.py`, using hand-authored expected tables for binary/arms inputs × missing answer/block × judge absent/failure × regex timeout. Exercise CLI → artifact → report; retain existing scoring semantics while requiring visible completeness counts. Healthy complete input must pass; dropping the partial-result counter or empty-answer guard in a disposable copy must fail. Proposed command: `python -m pytest -q tests/test_reference_completeness.py`. Evaluation maintainer; estimated 1–2 days, PR advisory budget 60 seconds/1 GB. Exclude real judge validity and stochastic quality.

2. **R2: inspection receipt pilot.** Extend `script_checks.py` and `tests/test_catalog_validate_scripts.py` with inspected/skipped counts and reasons, preserving existing findings compatibility. Fixtures cover valid/invalid Python, missing Bash, oversized file, cap boundary, and checkout-root exclusion. Oracle: independently specified counts; negative control removes a skip reason. Proposed command: `python -m pytest -q tests/test_catalog_validate_scripts.py`. Catalog maintainer; estimated 2–3 days, PR advisory budget 90 seconds/1 GB.

Both pilots should reuse existing outcome contracts, capture revision/toolchain, selected/executed/pass/fail/skip counts and JUnit under CI artifacts, and reject empty selections/timeouts as verification. Review ten advisory runs before proposing required-check configuration. Maintain on schema/parser/report changes; rollback blocking policy to advisory while retaining receipts. Defer SMT/Lean and broad mutation campaigns: the immediate gaps concern observable evidence semantics, not an identified theorem or concurrent protocol. Human usability, real judge calibration, distributed recovery, ABI compatibility and load performance remain outside this scope; logic, input boundaries, numerical aggregation, oracle strength, artifact compatibility, architecture and CI were inspected statically without coverage percentages.
