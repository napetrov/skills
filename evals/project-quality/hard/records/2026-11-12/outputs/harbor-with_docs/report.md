# Harbor assessment

The analyzer accepts incompatible records, while its dashboard reports 100%. The critical issue is silent corruption of supported consumers, not missing platform coverage.

**Scope and evidence.** Inspected all seven project files at clean revision `26f4965de7a0c9a3a73c45d29873ff2e962f901d`; no target changes or network access. README.md:2–7 defines eight packed little-endian layouts, signed-32-bit field values, and named-value preservation. Windows, native alignment, source ABI and floating point are excluded. Python 3.12.14 on Linux little-endian executed the documented unittest command: two tests passed, none skipped, exit 0. `python cli.py` returned nine generated/nine passed/100%. Reproduce the additional checks with `PYTHONDONTWRITEBYTECODE=1 python probe.py` and `python negative_control.py` from this report directory; scripts and captured outputs accompany this report. Combined baseline/probe runtime was measured at 0.145 seconds; deterministic, no seed. CI configuration was not-found-in-inspected-scope; live runs and enforcement evidence are unavailable (README.md:11). Local success establishes neither configured nor enforced checks.

**R1 — size equality does not preserve named values.** Consumer journey: new producer `encode(new, values)` → old consumer `decode(old, bytes)` (codec.py:6–10). `compatible` checks only total size (rules.py:4–5), ignoring name offsets and signed widths. With old `[('a',4),('b',4)]`, new `[('b',4),('a',4)]`, and values `{a:7,b:11}`, classification is true but the consumer reads `{a:11,b:7}`. With old `a4,b8` and new `a8,b4`, it reads `{a:7,b:47244640256}`. Both are explicitly supported changes. The unequal-size path correctly returns false; attempting old `a4,b4` decoding of new `a8,b4` raises `struct.error` rather than preserving values.

The probe independently exercised all 64 ordered layout pairs with 25 value combinations from `[-2**31,-1,0,1,2**31-1]`: 1,600 executions, 268 correct reads, 332 wrong reads and 1,000 expected buffer-size errors. Of 24 pairs labeled compatible, 16 have concrete counterexamples; eight identical pairs preserve all sampled values. No sampled false negatives. These counts cover the layout domain, not all possible values. Exact layout equality is sufficient by matching codecs; every other supported pair has a witness, so it also characterizes compatibility within this declared universe.

**R2 — generated coverage and expected answers conceal R1.** `generate.py:11–14` enumerates 64 pairs but retains nine total-size pairs, discarding order/width distinctions, and computes expectations with the same classifier being checked. `test_generated` therefore compares implementation against itself (tests/test_rules.py:7–10). The sole consumer assertion checks one unchanged layout (lines 11–13). Dashboard arithmetic is accurate for these nine tautological checks, but is not evidence of contract validity. A process-local always-true mutation passed both tests and still reported 100%; see negative_control.txt. No source mutation was needed.

**Two proposed implementation work items, in priority order:**

1. **Repair the contract and consumer regression tests.** Maintainer role (unassigned): change rules.py and add tests/test_contract.py using unittest. For supported inputs, require matching ordered names and widths. Independently enumerate eight layouts; assert all 64 classifications against the contract, and run new-writer/old-reader checks on the 25-value grid, with explicit mismatch/error witnesses for rejected pairs. Keep expectations independent of `compatible`. Proposed command: `PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -v`. Acceptance: corrected classifier passes; current size-only and always-true mutants fail; empty selection/skips cannot count as verification. Estimated effort: half a day.

2. **Make release evidence meaningful.** Update generate.py, cli.py and add tests/test_dashboard.py to retain 64 unique ordered pairs, source expectations independently, and assert dashboard counts plus the consumer evidence separately. Include unequal-size rejection and distinct-value reorder failures. Proposed workflow `.github/workflows/contract.yml`: PR/push advisory unittest runs, then required-check promotion after stable measured runs and explicit protection configuration. Negative control: collapsing to nine representatives must fail. Estimated effort: half a day.

Both pilots: estimated budget 10 seconds/256 MB, no dependency cache needed; save revision, environment, counts and counterexamples as CI artifacts. Review on contract/codec changes; maintainer may revert a noisy gate to advisory while preserving evidence. Performance/load, concurrency and AI evaluation are inapplicable to this bounded synchronous sample; build reproducibility and malformed-input guarantees lack evidence. Defer property-testing frameworks, formal provers and platform matrices: exhaustive layout enumeration plus independent consumer witnesses directly addresses the present risk.
